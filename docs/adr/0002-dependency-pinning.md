# ADR-0002: 依存管理を uv（pyproject.toml + uv.lock）に移行する

## ステータス
Accepted（2026-09-24）

## 文脈

- `requirements.txt` にバージョン指定が無く、Render は毎デプロイで最新版を取得している
- `asyncpg` と `protobuf` は requirements.txt にあるが、ローカル venv に無い（= 本番にだけ入っている）。`protobuf` はコード中で一度も使われておらず、`asyncpg` は `scripts/` の2本からしか参照されず `main.py` の import グラフには含まれない
- インストール済み32個のうち直接依存は6個。残り26個は推移的依存（`starlette`, `httpx`, `anyio` など、誰も指定していないが入るもの）で、**requirements.txt に `==` を書いても固定されない**
- Python のバージョンが固定されていない。`.python-version` も `runtime.txt` も無いため、Render がどのバージョンを使っているか不明。ローカルは 3.10.3
- **Python 3.10 は 2026-10-31 に EOL。** 37日後にセキュリティ修正が止まる
- Week 1 でテストを導入する予定がある。テストの失敗原因が2つ（自分の変更／依存の更新）あると、警報として機能しない

### 経緯：当初の判断を覆した理由

- 当初は `requirements.txt` の `==` 固定で進める判断をした。uv を却下した理由は「移行が Render のビルド設定変更を伴うため、地図機能の前に本番のデプロイ経路を触りたくない」だった
- しかし Render の Python ネイティブランタイムは **uv を同梱しており**、`uv.lock` をルートディレクトリに置けば利用できる。実際の変更は Build Command の1行差し替えのみだった
- **却下理由は、コストを検証せずに高いと仮定したものであり、事実として成立していなかった**
- この誤りは「却下理由を ADR に書いた」ことで検証可能になり発見された。理由を書かずに「lock は使わない」とだけ記録していた場合、誤りは残り続けていた

## 決定

- **uv を採用する。** `backend/pyproject.toml`（意図・人間が書く・`>=` 範囲）と `backend/uv.lock`（事実・uv が生成・全パッケージを `==` とハッシュで記録）の2ファイル構成にする
- **Python は 3.13 に固定する。** `backend/.python-version` に記述する。Render のネイティブランタイムと uv がどちらもこのファイルを読むため、1ファイルで両方に効く
- 使われていない `protobuf` と `asyncpg` は移行時に持ち込まない
- `uv.lock` は git にコミットする。`.venv/` はコミットしない（既に .gitignore 済み）
- `requirements.txt` は **Render の切り替え完了を確認した後に削除する**。同時に消すとビルドが失敗する
- Render の設定を次のように変更する

| 項目 | 変更前 | 変更後 |
|---|---|---|
| Root Directory | `backend` | 変更なし |
| Build Command | `pip install -r requirements.txt` | `uv sync --frozen` |
| Start Command | `uvicorn main:app --host 0.0.0.0 --port $PORT` | `uv run uvicorn main:app --host 0.0.0.0 --port $PORT` |

- Build Command に `--frozen` を付ける。`uv.lock` を**読むだけ**でビルド中に書き換えさせないため。これを外すと本番で依存が再解決され、固定した意味が失われる

## 結果

### 得たもの

- **推移的依存26個を含む全パッケージがバージョン固定される。** `==` 固定では守れなかった範囲が埋まる
- **ハッシュが `uv.lock` に記録され、配布物の改ざんを検知できる。** バージョン番号だけでは守れなかった「中身の同一性」が保証される
- **Python のバージョンも固定される。** 3.10 EOL 問題が同じ作業で解決する
- テストが落ちたとき、原因が自分の変更に絞られる（テストが警報として機能する）
- 意図（`>=` 範囲）と事実（`==` 固定）が別ファイルに分かれ、どちらを編集すべきか迷わなくなる
- 開発用依存を `[dependency-groups]` で本番と分離できる。Week 1 の pytest 導入で使う
- 本番にだけ入っていた不要な2個が消え、ローカルと本番の差が縮む

### 諦めたもの

- **Render のビルド設定に手を入れる。** 切り替え時に一度、本番のデプロイ経路を触るリスクを負う
- **Python 3.10 → 3.13 の跨ぎが同時に起きる。** 失敗したとき原因が2つ（uv / Python バージョン）になりうる。緩和策として、Render に触る前にローカルで 3.13 の動作を完全に確認することを移行手順の関門に置く（詳細は計画書 付録D）
- pip しか知らない状態から、uv のコマンド体系を覚える学習コストが発生する
- ローカルの `venv/` を捨てて `.venv/` を作り直す。CLAUDE.md の起動手順も書き換えが必要になる
- `uv` はローカル環境に別途インストールが必要（Render 側は同梱済み）

### 再検討のきっかけ

- uv の開発が停止、または Render がネイティブサポートを外したとき
- Python 3.13 で動作しないライブラリが必要になったとき
- 推移的依存の自動更新が必要になったとき（Renovate / Dependabot の導入を検討する）
